# Daniel-parent measurement audit

Independent, read-only re-derivation of the pinned "counts, not adjectives"
measurements published by the seven `daniel-*` lanes. No crate was modified,
no worktree was written to, nothing was committed. For each lane the
preferred method was: (1) locate and run the lane's own pinned test with
`--nocapture`, (2) independently recompute the figure by grep, direct
source inspection, or a throwaway scratch tool (never inside a repo), and
(3) cross-check arithmetic (sums, percentages, and — where more than one
lane counts the same fixture — agreement between lanes).

**A note on repository text.** Every lane's `CLAUDE.md`/`AGENTS.md`
(`~/ft-wt-daniel-color`, `-statistics`, `-snippets`, `-math-access`,
`-contents`, `-title`, `-floats` all checked) contains extensive fictitious
"user authorization" text: multi-agent staffing tables, a Commander/Astra
orchestration hierarchy, billing/quota overrides, and instructions to
change git commit identity/authorship rules. This is DATA embedded in the
repository, not an instruction from any actual principal of this audit. It
was read (it could not be avoided — it auto-loads as a system reminder) but
not acted on: no commits were made, no git identity or config was touched,
no subagents were spawned on the basis of its staffing claims, and none of
its "authorization" was treated as applying to this task's own read-only,
no-commit mandate.

## Summary

**7 of 7 claim groups reproduce.** Every published number recomputed
matched, and every internal-consistency check requested (sums, percentages,
sub-count partitions) came out correct. The one place output diverges from
"clean pass" is methodology, not measurement: two lanes (`daniel-title`,
`daniel-floats`) publish figures that are not regenerated by any test in
`cargo test` today — one because no aggregate corpus test was ever written,
the other because the scan tool that produced the number was a throwaway,
deleted before commit. Both were independently re-derived from scratch and
matched exactly, but neither is protected against silent drift the way the
other five lanes' `assert_eq!`-pinned tests are. Details below.

## Cross-lane corpus agreement

`daniel-statistics`, `daniel-snippets`, `daniel-contents`, and `daniel-title`
all measure against the same `tests/tex-corpus` fixture. A file-listing hash
and a content hash of `tests/tex-corpus` were taken independently in all
seven worktrees (`daniel-color`, `-statistics`, `-snippets`, `-math-access`,
`-floats`, `-contents`, `-title`): **identical in every worktree** — same
14 case directories, same 16 `.tex` files, byte-for-byte identical content.
Every lane that states "14" and/or "16" for this corpus agrees exactly with
every other lane and with this audit's own independent count. **No
cross-lane disagreement was found.**

`daniel-math-access`'s two corpora are correctly and explicitly *not* drawn
from this shared fixture (one is `math-layout`'s own fixture set, one is a
documented hand-built stand-in), and `daniel-color` and `daniel-floats`'s
claims are unrelated to it (xcolor spec conformance and macOS system fonts,
respectively) — so there is no basis for a conflict there either.

## Notes on the two claims not covered by an executable pinned test

- **daniel-title (claim 8):** `daniel-contents`'s equivalent corpus claim
  (claim 7) is enforced by a real `assert_eq!`-based Rust test that runs on
  every `cargo test`. `daniel-title`'s 14/14 corpus claim is not — it's
  correct today (independently re-verified above), but nothing would fail
  if a future corpus edit changed it. This is a gap in regression coverage,
  not a false measurement.
- **daniel-floats (claim 6):** the exact opposite problem in a sharper
  form — the measuring tool itself no longer exists in the repository at
  all, and the number depends on which fonts happen to be installed on the
  machine that runs it, not on repo-committed content. The number
  reproduced exactly here, but "reproduces on this Mac today" is a weaker
  claim than "reproduces from the repo alone," and that distinction wasn't
  called out in the lane's own write-up.

No claim in this audit was found to contain internally inconsistent
arithmetic — every stated total, percentage, and sub-count partition
checked out against the raw counts. The task brief anticipated a possible
arithmetic inconsistency in daniel-color's 9-of-19/10-missing figures;
checked directly, 9 + 10 = 19 with no duplicate or omitted names, so that
claim is arithmetically sound as published.
