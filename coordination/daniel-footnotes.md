## What I salvaged (verified against `origin/main`, then hand-picked)

one generator script, all self-contained (no dependency on the oracle

else needed to move):

- `src/metrics.rs` — new `Extensible` glyph-recipe struct; three new
  default trait methods on `MathFontMetrics` (`delimiter_extensible`,
  `radical_extensible`, `text_glyph`), all with safe defaults, so existing
  implementors (font-engine's `OpenTypeMathFace`) are unaffected.
- `src/times.rs` — one-line fix so `TimesApproxMetrics::params` picks up
  the base CM params it was previously silently dropping.
- `src/cm.rs` — extensible-recipe lookups for delimiters/radicals (reads
  the TFM `next_larger`/extensible chain to the end and stacks the
  bot/rep/mid/top pieces), a `latex_12pt()` constructor, `text_glyph`
  (roman family, for `\lim`/`\sin`-style operator text), `\imath`/`\jmath`
  symbol slots.
- `src/cm_tfm.rs` — additional embedded TFM data for cmr/cmmi 12/8/6pt and
  cmsy8/6, generated by (the also-updated) `tools/gen_cm_tfm.py`, needed by
  `latex_12pt()`. Pure data, mechanically generated, not hand-edited.
- `src/mathlist.rs` — extends `Nucleus::Radical` to a struct variant with
  an optional `degree` (`\sqrt[n]{}`), adds `Nucleus::Text` (upright
  operator text), `Nucleus::Overline`/`Underline`, `Nucleus::Styled`
  (explicit `\displaystyle`-etc override), plus matching `Atom::root`,
  `Atom::text_op`, `Atom::overline`, `Atom::underline`, `Atom::styled`
  constructors.
- `src/layout.rs` — the actual box-construction work: extensible glyph
  stacking (`stack_extensible`, tex.web §713) for delimiters and radicals
  once every fixed size is too small; `\sqrt[n]{}` degree geometry
  (LaTeX's `\r@@t` kern/raise recipe); accent-over-scripted-character
  handling (tex.web §738/§742 — scripts move under the accent, accent
  re-centers, box grows to clear them); `make_text` for upright operator
  text; `make_over`/`make_under` (Rules 9/10, explicit rule primitives,
  never a flattened glyph).
- `tests/golden.rs` — 9 new tests plus one renamed/adjusted, all numeric,
  cross-checked against real pdfTeX 1.40.29 `\showbox` output at 5-decimal
  precision (method already established by the existing test file, not
  something I introduced): extensible brace stacking, extensible radical
  stacking, `\sqrt[3]{}` degree geometry, `\lim`/`\sin` limits vs.
  no-limits with italic-correction spacing, overline/underline rule
  geometry, accent-over-scripted-char, `\widehat` chain widening, nested
  explicit style overrides, and a property test across every fixture ×
  style × both metrics providers asserting no box-drawing glyph is ever
  emitted for a rule and the rule count matches the AST exactly (guards
  against the old "flattened fraction bar as a glyph" failure mode).

## API changes consumers must know about

- `Nucleus::Radical(MathList)` → `Nucleus::Radical { radicand: MathList,
  degree: Option<MathList> }`. This is source-breaking for anyone
  pattern-matching that variant directly. The only in-repo consumer
  (`font-engine`) does not reference `mathlist` at all, so nothing in this
  repo breaks. `Atom::sqrt(radicand)`'s signature is unchanged; the new
  shape is only visible if you match `Nucleus` directly.
- `MathFontMetrics` gained three new trait methods, all defaulted, so no
  existing implementation needs changes.
- Everything else is additive (new `Atom`/`Nucleus` constructors, new
  `CmMathMetrics::latex_12pt()`, new `metrics::Extensible`).
