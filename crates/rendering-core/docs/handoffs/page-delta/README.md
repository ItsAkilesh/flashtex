# Rendering consumer requirements for an opt-in page/delta proposal

Review baseline: rendering branch `96c66f2af7914d803473746e9c03bd6fcd3667e0`. Proposal inputs: issue 2 comments `5646277113` and Commander ruling `5646362851`. This is a reviewable handoff to the existing producer/native/helper owners, not a negotiated schema or implementation. Existing full replies and decline behavior remain unchanged.

## Existing full-list acceptance boundaries

| Layer | Current checks relevant to reconstruction |
| --- | --- |
| `src/lib.rs::parse` and `DisplayList::validate_profile` | Existing serde typed decoding, duplicate/unknown typed fields refused; known message/primitive enums; 32 MiB generic input ceiling; explicit feature support; exact bounded integer ticks, finite bounded paint, checked geometry arithmetic. Pages are contiguous and ordered `1..N`, N may be zero and is at most 10,000. At most 100,000 items/page, 256 fonts, 4,096 declared documents, 10,000 diagnostics. |
| Glyph/provenance validation | Original GID in declared font bounds; exact cluster partition of UTF-8 run text, glyph-to-cluster closure, bounded hit rectangles/carets; exactly source ranges or explicit synthetic provenance. No inferred caret-to-TeX byte correspondence. Ordered items, page dimensions, source spans, text, advances, hit geometry and paint all matter even when painted pixels match. |
| `src/pipeline_frame.rs::pair` | Each result/sibling at most 16 MiB; v1 status/capability correlation and exact request/project/compile revision. Failed result cannot accept sibling; accepted capability exactly matches sibling presence. Strict helper route refuses `tfm_missing`, `required_metrics_unavailable` or error diagnostics. Pairing alone does not verify resources. |
| `src/pipeline_cff.rs::bind_list` | Explicit CFF profile; every declared source resolves to caller bytes with exact revision/SHA/length. Every font resolves to immutable verified resource with exact raw font SHA, face, byte length, UPEM, GID count and PostScript name. Cluster/rule/diagnostic ranges are checked against actual UTF-8 source boundaries. SourceRange itself contains path/start/end only; source revision/hash belongs to global document metadata. |
| `src/helper_candidate.rs::bind` | Full-event 16 MiB limit, existing finite/depth visitor including ignored extensions; original-byte typed decoding. Requires explicit untrusted candidate with source actions disabled. Exact caller-owned session/project/request/compile/membership identity and all path/editor-version membership, <=256 sources; maps those current bytes into the compile snapshot. An event cannot supply its own authority. |
| Retained use | Bound resources and display are immutable. Every searchable export and read-only hit call requires fresh exact `CurrentHelper` equality, including source bytes, versions and membership generation. A→B→A must change controller generation. Hit index is private/lazy per immutable bound candidate. PDF export refuses error diagnostics and has its own <=256-page and byte-budget gates. No source-action/native paint authority follows from any of these checks. |

The limits differ by layer; the proposal must not advertise the generic parser ceiling as helper capacity. Existing semantic bounds mostly apply after typed allocation. A smaller wire delta alone does not bound decoded/reconstructed residency.

## Required complete-snapshot reconstruction contract

The owner schema must identify an exact acknowledged base snapshot and a separate new snapshot within the current session/project/generation namespace. A content hash alone cannot establish freshness or replace caller authority. Include the new full ordered page count and an unambiguous mapping of every destination page to either an exact base page or supplied replacement. Define removal, insertion, renumbering and zero-page output; reject duplicate destinations, holes, overlap, missing base pages and ambiguous reuse. Existing page.number is part of the page semantics, so shifted pages cannot be silently relabeled under their old hash.

Digest scope must cover **all** retained semantics, including page size/order/items, source/hit/caret information, text, paint, full font declarations and required features. Specify whether identity hashes exact bytes or a defined canonical representation. Existing raw captures preserve number spellings/escapes; arbitrary typed reserialization does not prove byte-identical fresh output. If the gate promises raw-byte equality, define framing/serialization and retain sufficient original bytes. Otherwise explicitly distinguish semantic equality from raw equality, subject to the Commander's ruling.

Rebuild the complete new global document/font tables, required features and diagnostic sequence along with pages. Unchanged page pixels or GIDs do not imply unchanged source binding. A retained path/offset must be checked against the new authoritative source bytes and metadata, including UTF-8 boundaries. Resource closure includes unchanged pages: removing a font still referenced by a retained page must refuse. Reusing a font_id with changed bytes must resolve to the new verified immutable identity, never a stale cache entry. Preserve original GIDs and raw-font versus engine identity distinctions.

Only after complete reconstruction, digest verification, existing full-list validation, v1 correlation, immutable resource binding and fresh helper currentness may the new candidate be atomically published. Reuse the existing full validator/binder; do not introduce an unchecked constructor or alternate permissive parser. Keep the old immutable snapshot intact on any failure. A visibility-filtered subset is a distinct incomplete view and cannot be passed to complete export or enable source actions; this review does not authorize a subset API.

## Bounded state and lifecycle requirements

Specify numerical caps for delta bytes, entries, retained bases, total retained raw and decoded bytes, font/outline/index residency, reconstruction peak and pending updates. A bounded initial design can retain one acknowledged base plus one bounded private candidate, sharing immutable resources, with explicit refusal when peak budget cannot accommodate reconstruction. This is a proposed policy, not an implemented cap. Count external retained references separately; dropping a cache entry does not free an Arc held by an old frame.

Wrong/missing/evicted base, rejected delta, cancel, supersession, reset or process/session restart must not mutate the base or promote a partial snapshot. Recheck current authority after asynchronous work and immediately before publication/use. Specify whether cancellation retains the old complete base and require an exact acknowledged identity before any later reuse. Missing state requires a full resync under existing bounds; if full output itself exceeds bounds, surface refusal and preserve durable source/old preview rather than silently truncating. Do not assume a large-source transport failure is solved by deltas.

No incomplete candidate may become exportable while waiting for remaining pages. Do not merge out-of-order deltas by request ID alone, carry old diagnostics forward by default, or treat absence of changed-source pages as proof that membership stayed constant.

## Bounded acceptance plan for owners

Use one existing actual producer fixture and its fresh full result as the oracle for reconstruction, without source rewriting. Exercise: unchanged page reuse; insertion/deletion/reordering and zero pages; unchanged paint with changed source revision/span; UTF-8/ligature provenance; font replacement under the same label; removed referenced resource; diagnostics appearing/disappearing; wrong/evicted base; duplicate changed page and conflicting removal; incomplete update; cancellation/restart and late old-session callback; bounded oversize refusal with old frame retained. Check exact full geometry/text/source/resource/diagnostic equality and, separately, the promised byte equality. Keep stale export/hit refusal gates after reconstruction. No native latency or visual-parity claim follows from these tests.

The native owners still need to publish the actual schema and negotiation/reset rules. This handoff neither picks a capability name nor edits Commander-owned contracts. It introduces no parser, wire switch, native source change, corpus run or new cache.
