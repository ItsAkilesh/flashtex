# R4 remaining bounded-state review

Pinned producer proposal `0569b74` (no wire activation). R4 fixes the previous explicit over-cap paint path: it now rejects reconstructed targets before building or painting them, and identifies installed, in-flight and queued objects separately. Running callbacks are no longer claimed to disappear when a queued item is replaced. These address the intended policy of our refusal scenarios, subject to actual implementation gates.

The proposed *charge function* still does not establish the claimed conservative cap. `display.rs::estimated_json_bytes` at producer `9aaec57a` charges a fixed 280 bytes per cluster and 200 per document, ignoring variable hit/caret/source counts and path bytes. The accepted full model permits 128 hit rectangles and 128 carets per cluster and long document paths; these cannot generally fit those fixed charges. An observed 8% overestimate on one fixture is not an upper-bound proof. The existing producer protects itself with an actual serialized-length check after the estimate; a reconstruction preallocation budget cannot assume that later protection. Use checked accounting over all variable fields or explicitly restrict the admissible profile and prove its bound before relying on cached base estimates.

R4's raster term names the painted frame, but existing `V2Loader` prerasterizes the new frame off-main before delivery. That new raster/CGFont/prepared-page residency exists simultaneously with old frame resources, active models and queued bytes. Charge both old and in-flight resource sets, retained callbacks and relevant caches, with explicit refusal/backpressure caps if claiming a total bound. Clearing the reconstruction chain while keeping the last painted frame also retains its resources; base eligibility is not reclamation.

No new delta decoder, implementation, allocation probe or corpus run was added. The existing illustrative Appendix A gates are unchanged from our pinned r3 run; do not call them native or resource-budget acceptance. Target rejection and slot names improve the design, but estimator/resource accounting prevents an activation ACK.
